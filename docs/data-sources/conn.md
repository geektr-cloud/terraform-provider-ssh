# ssh_conn (Data Source)

Performs a real SSH connection probe and returns a complete, sensitive Connection Profile. The probe must complete a real SSH handshake and authentication; only then is `conn` returned. A failed probe blocks dependent resources from opening connections in parallel.

Each consumer of `conn` reconnects independently for every Terraform lifecycle operation. The provider does not keep live connection handles, process-global maps, or external daemons.

~> The returned `conn` object and the input `private_key` are sensitive but are **not encrypted** by the provider. They are persisted in plan and state because managed resources and later CLI runs need them for destroy. Use encrypted state storage and least-privilege access.

~> `Read` uses the prior state. If a private key is rotated and the old key is no longer accepted, refresh fails. Either update the state credential or run with `-refresh=false` while rotating. See the README for the full rotation procedure.

## Example Usage

```hcl
data "ssh_conn" "server" {
  host        = "203.0.113.10"
  port        = "22"
  user        = "deploy"
  private_key = file("~/.ssh/id_ed25519")

  known_hosts = "~/.ssh/known_hosts"
  envs        = { LANG = "C" }
  timeout     = "5m"
  retry_delay = "5s"
}
```

Host verification uses exactly one mode:

- `known_hosts`: a known_hosts file path. `~` is expanded. The file must exist; TOFU is not used.
- `host_key`: an inline fixed host public key in authorized-key format.
- `insecure_ignore_host_key = true`: explicitly disable verification.

When all three are omitted, `~/.ssh/known_hosts` is used.
