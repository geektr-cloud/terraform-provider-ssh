# SSH Provider

The SSH provider manages remote files and directories, and performs one-shot file reads and command execution. It targets Linux hosts with GNU coreutils `install`, `timeout`, and `mktemp` available.

Connection settings live in two layers. The `provider "ssh"` block holds optional Provider Connection Defaults shared by every consumer. Each `ssh_resource`, `data.ssh_data`, `data.ssh_sensitive_data`, and `ephemeral.ssh_data` may set `conn` to a Sensitive JSON object string that overrides only the fields that differ. Built-in defaults fill whatever remains.

- Omit `conn`, set JSON `null`, or set `{}` to inherit the provider defaults unchanged.
- JSON absent fields inherit; JSON `null` clears the provider value and returns to the built-in default; explicit `envs` merges by key; `jump` replaces the whole jump profile.
- JSON must be an object or `null`. Unknown fields, duplicate keys at any level, arrays, scalars, and wrong value types are rejected with a field path, never the raw JSON or secret values.
- Only `conn` from the configuration is persisted by ordinary consumers. Provider-level private keys never enter resource or data source state. A private key written inside `conn` does.

Use `provider::ssh::connection(host, user, port)` to build a JSON override for a dynamic target without network access, key material, or provider reads.

-> When an identity change triggers replacement, Read and Delete still use the current provider defaults and override, not the prior identity. Ensure same-named paths on the current endpoint are safe to refresh and delete; otherwise restore the old endpoint and destroy first.

-> The provider requires Terraform or OpenTofu 1.11 or later because `ssh_resource.file.content_wo` uses write-only attributes. Provider functions require 1.11 or later as well.

## Example Usage

```hcl
terraform {
  required_providers {
    ssh = {
      source = "geektr-cloud/ssh"
    }
  }
}

provider "ssh" {
  host        = "example.internal"
  port        = "22"
  user        = "deploy"
  private_key = file("~/.ssh/id_ed25519")
  known_hosts = "~/.ssh/known_hosts"
  envs        = { LANG = "C" }
  timeout     = "5m"
  retry_delay = "5s"
}

resource "ssh_resource" "config" {
  directory {
    path = "/etc/myapp"
    mode = "0755"
  }

  file {
    path    = "/etc/myapp/config.yaml"
    content = "listen: 0.0.0.0:8080\n"
    mode    = "0644"
  }
}
```

!> Provider-level connection defaults are Sensitive in the provider schema, but Sensitive only redacts display. The provider private key is not copied into consumer state, but a private key placed in a consumer's `conn` JSON is persisted. Use encrypted remote state and restrict access.

## Schema

### Optional

- `envs` (Map of String) Default environment variables for command and run operations. Consumers merge their own `envs` by key.
- `host` (String) Default target host.
- `host_key` (String) Default inline fixed SSH host public key in authorized-key format.
- `insecure_ignore_host_key` (Boolean) Explicitly skip host key verification for default connections. Never enable this without understanding the risk.
- `jump` (Attributes) Optional default single jump host. A consumer `jump` replaces this profile as a whole. (see [below for nested schema](#nestedatt--jump))
- `known_hosts` (String) Default known_hosts file path. `~` is expanded; the file must exist when a connection is opened.
- `port` (String) Default SSH port, as a string between 1 and 65535. Defaults to 22.
- `private_key` (String, Sensitive) Default inline private key. It is not persisted in consumer state; consumers that put `private_key` in their own `conn` JSON still persist that copy.
- `retry_delay` (String) Default delay between retries for transient network failures. Defaults to 5s.
- `timeout` (String) Default dial and retry budget, including the jump connection. Defaults to 5m.
- `type` (String) Target type. The only supported value is `linux`. Defaults to `linux`.
- `user` (String) Default SSH user.
